# Nell v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Nell, a floating pixel-art macOS companion. She drives Claude Code and a tools-off Claude chat running in a kitty instance she owns, and she shows their state through animations and fading speech bubbles with Allow/Deny approvals.

**Architecture:** A SwiftPM package with two targets:
- `NellCore` holds all the pure, tested logic: hook event decoding, the state machine, bubble rules, approval registry, launch-argument builders and HTTP parsing.
- `Nell` is the AppKit/SwiftUI app: the overlay panel, the Unix-socket hook server and the kitty controller.

Claude always runs inside kitty. Nell starts each `claude` with `--settings` pointing at hook config that calls `hooks/nell-hook.sh`. That script forwards each event to Nell's fixed Unix socket and falls back to raising kitty if Nell can't be reached.

**Tech Stack:**
- Swift 6.4 from the Command Line Tools (there is **no Xcode**: use `swift build` and `swift test`, with **Swift Testing**, `import Testing`; XCTest isn't available).
- AppKit `NSPanel` hosting SwiftUI.
- POSIX `AF_UNIX` sockets.
- kitty 0.50.0 remote control.
- Claude Code 2.1.321.
- `bash`, `curl` and `jq` for the hook script.

**Spec:** `docs/superpowers/specs/2026-11-14-nell-desktop-companion-design.md`. Read it alongside this plan. The research behind the "Lessons" section is in `reports/Claude companion apps landscape.md`.

## Global Constraints

- macOS only, `platforms: [.macOS(.v14)]`. The app bundle is `Nell.app` with `LSUIElement = true` (no Dock icon).
- Never read or write `~/.claude/settings.json` or `~/.claude.json`. Hooks reach Claude only through `claude --settings <file>`.
- Binaries:
  - kitty: `/Applications/kitty.app/Contents/MacOS/kitty`
  - kitten: `/Applications/kitty.app/Contents/MacOS/kitten`
  - claude: `~/.local/bin/claude`
  
  None of them are on PATH inside hooks, so always use absolute paths.
- The support directory `~/Library/Application Support/Nell/` holds:
  - `nell.sock` (Nell's server, mode 0600)
  - `kitty-{kitty_pid}.sock`
  - `kitty.conf`
  - `hooks-code.json` and `hooks-chat.json`
  - `nell-hook.sh`
  - `state.json`
  - `chat/`, Chat mode's working folder
- One writer per session: only the `claude` process in kitty. Nell never runs `--continue`. Each session gets `--session-id <uuid>` when it's created and `--resume <uuid>` after that.
- Chat flags: `--tools ""` `--strict-mcp-config` `--setting-sources project`, plus `--settings hooks-chat.json`. **Never** `--bare` or `--safe-mode`.
- The approval script waits 590 s. The hook `timeout` is set to 600 s in the settings files.
- Non-blocking hook calls give up after 0.5 s (`curl -m 0.5`) and exit 0 with no output.
- Window: a non-activating `NSPanel`, level `.screenSaver`, collection behaviour `[.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]`, `hidesOnDeactivate = false`. Only the bar takes key focus.
- Animation runs at 6–12 fps and redraws only when the frame changes. It stops when Nell is sleepy, the screen is locked or the display is asleep.
- Pinned timings (all in one place, `NellCore/Timings.swift`):
  - oops beat 1.5 s
  - done beat 3 s
  - typing watchdog 180 s
  - sleepy after 600 s idle
  - hooks-not-connected after 8 s
  - bubble visible 20 s (Chat reply 60 s), then a 2 s fade
  - at most 4 visible bubbles
- The global hotkey is ⌥⌘N, registered through Carbon `RegisterEventHotKey` so it needs no Accessibility permission. Check that it doesn't clash with anything on this Mac.
- Sound: `NSSound(named: "Tink")`, only for needs-you, and skipped when kitty is the frontmost app.

## Review Focus

1. **Prompts with quotes, newlines, `$`, backticks or emoji** typed into the bar must reach Claude as one prompt, exactly as typed. Covered by Task 6's argv test and the multi-line check in Task 9.
2. **Two approvals pending at once** (subagents or parallel tools): each bubble settles only its own request, and closing one never denies another. Covered by the Task 5 `ApprovalRegistry` tests.
3. **Nell crashes or is force-quit while sessions are running.** On relaunch she reuses the live kitty and doesn't start a second one, rebinds the same `nell.sock` after removing the stale file, and the running `claude` hooks reach her again. Covered by Task 5 (stale socket rebind) and Task 6 (`pickKittySocket`).
4. **Project folders with spaces or non-ASCII names** such as `~/My Projects/日本`: `claude` starts in the right folder and the saved-session check finds the transcript. Covered by the Task 3 `transcriptPath` tests.
5. **Huge hook payloads**, such as a `Write` with a 1 MB `content`, or a 20 KB reply. The server reads the whole body even when it arrives in pieces, and bubbles truncate. Covered by the Task 2 chunked-parse test and the Task 4 summary truncation test.

### Task 4: State machine, body priority and tool summaries

**Files:**

  - `struct SessionTracker { private(set) var state: NellState; mutating func tick(now: Date); mutating func markLaunched(now: Date); mutating func handle(_ e: HookEvent, requestId: String?, now: Date)` (the event plus the server's request id for `PermissionRequest`); `mutating func settleApproval(_ requestId: String, answer: ApprovalAnswer)`; `private(set) var pendingApprovals: Set<String>`; `private(set) var pendingQuestion: String?`; `var inputHeld: Bool` }`. Move `enum ApprovalAnswer: Sendable { case allow, deny, none }` here from Task 5, so Task 4 can use it.
  - `func bodyState(selected: Mode, code: SessionTracker, chat: SessionTracker, listening: Bool) -> NellState`
  - `func toolSummary(name: String, input: [String: JSONValue]?) -> String`

Rules to encode (from the spec's state table and "Lessons"):
- `UserPromptSubmit` → `thinking` and clears "finalized".
- `PreToolUse` → `typing`, but `AskUserQuestion` → `question`.
- `PostToolUse` → `thinking`.
- `PostToolUseFailure` → `oops` for 1.5 s, then `thinking`.
- `PermissionRequest` adds its `requestId` to `pendingApprovals`, giving `needsYou` while that set isn't empty. Only `settleApproval` removes an id. Other events never settle an approval: a second request or a subagent's `PreToolUse` must not close an open one.
- `inputHeld` is true while `pendingApprovals` isn't empty or `pendingQuestion` is set. A settle with `.none` (Open terminal, or a timeout) means Claude's own prompt is now open in kitty, so `inputHeld` **stays true until the next event of any kind** from that session. A question is set by an `AskUserQuestion` `PreToolUse` and cleared by the next event from the session.
- `Notification` → `alert`, unless approvals are pending or the same `message` was already shown.
- `Stop` → `done` for 3 s, then `idle`, and *finalized*.
- `StopFailure` → `error`, finalized. `SessionEnd` → `idle`, finalized.
- While finalized, `PostToolUse` and `PreToolUse` are ignored. `SubagentStop` never changes the state.
- `tick`:
  - `typing` or `thinking` with no events for 180 s → `idle`
  - `idle` for 600 s → `sleepy`
  - launched with no `SessionStart` within 8 s → `disconnected`
- Priority in `bodyState`: `needsYou`/`question` (either mode) > `error`/`alert`/`disconnected` (either mode) > the selected mode's state > `listening` if the selected mode is idle.

### Task 5: Bubbles, approval registry and the hook server

**Files:**
- Create: `Sources/NellCore/BubbleStore.swift`, `Sources/NellCore/ApprovalRegistry.swift`, `Sources/NellCore/HookServer.swift`
- Test: `Tests/NellCoreTests/BubbleStoreTests.swift`, `Tests/NellCoreTests/ApprovalRegistryTests.swift`, `Tests/NellCoreTests/HookServerTests.swift`. `HookServer` lives in NellCore so it can be tested; it uses only Foundation and Darwin, no AppKit.

**Interfaces:**
- Produces:
  - `enum BubbleKind: Equatable { case user, reply, status, approval(requestId: String), question, alert, error }`
  - `struct Bubble: Identifiable, Equatable { id: UUID; kind: BubbleKind; mode: Mode; text: String; created: Date; settled: Bool; fadeStart: Date? }`
  - `struct BubbleStore`, with:
    - `mutating func add(_ kind: BubbleKind, mode: Mode, text: String, now: Date)`
    - `mutating func setStatus(mode: Mode, text: String, now: Date)`, which replaces that mode's single live status bubble
    - `mutating func settle(requestId: String, as label: String)`
    - `mutating func tick(now: Date, userIdle: TimeInterval, hovered: UUID?)`
    - `func visible(now: Date) -> [(Bubble, opacity: Double)]`
  - `final class ApprovalRegistry: @unchecked Sendable` (guarded by a lock), with:
    - `func wait(id: String, timeout: TimeInterval) -> ApprovalAnswer`, which blocks the connection's queue and returns `.none` on timeout or close
    - `func answer(id: String, _ a: ApprovalAnswer)`
    - `func closed(id: String)`, called when the hook connection closes
    - `var pendingIds: [String]`
  - `func approvalResponseBody(_ a: ApprovalAnswer) -> Data`: empty for `.none`; otherwise the JSON confirmed in Task 1
  - `final class HookServer`, with `init(socketPath: String, registry: ApprovalRegistry, onEvent: @escaping @Sendable (Mode, HookEvent, _ requestId: String?) -> Void, onRequestSettled: @escaping @Sendable (Mode, _ requestId: String, ApprovalAnswer) -> Void)`. `onRequestSettled` fires exactly once for each `PermissionRequest`: with the user's answer, or `.none` when the peer closes or the request times out, `func start() throws` and `func stop()`. `start` unlinks a stale file, binds, `chmod 0600`, then accepts. A `PermissionRequest` connection gets a `requestId` (UUID) and blocks on the registry until it's answered or the peer closes. Every other connection is answered at once with an empty body.

Bubble rules:
- The newest is last. At most 4 are visible, and older ones get opacity 1.0, 0.55, 0.3, 0.12.
- Unsettled `approval` and `question` bubbles never fade.
- `reply` and `error` bubbles start `fadeStart` only once `userIdle < 5 s`.
- A hovered bubble's fade clock pauses.
- A bubble fades after 20 s, or 60 s for a Chat `reply`, over 2 s, then is removed.
- Code `reply` text is cut to 3 lines plus "…more in ⌘". Chat replies are kept whole.

## Deviations from the spec (decided while planning)

- **The Chat folder isn't pre-trusted**, because that would mean writing to `~/.claude.json`, which the Global Constraints forbid. The `disconnected` state after 8 s shows kitty, so you accept the trust dialog once, and this covers broken hooks too.
- **`HookServer` lives in `NellCore`** so it can be integration-tested without AppKit.
