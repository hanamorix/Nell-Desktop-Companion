# Plumbing, not pixels, decides which companions survive

About a dozen desktop companions for AI coding agents meet the bar of more than 100 GitHub stars or recent development. Only a handful are healthy. **clawd-on-desk** (6.7k stars, 100+ contributors, 43 releases) is the only established *floating character pet* found that also handles approvals well. The rest of the leaders are notch or "Dynamic Island" status bars: **Open Island**, **Notchi**, **MioIsland** and the paid **Vibe Island**. The other large floating pets, Petdex and OpenPets, are watch-only as far as their READMEs show, and their weight sits in a sprite gallery and a plugin platform respectively. The baseline is now settled and widely copied: Claude Code hooks feed a local socket, a 7–12 state machine drives the animation, and the app adds Allow/Deny from the companion, jump-to-terminal and a fail-open fallback. Roughly 630 GitHub issues across six repos show that users rarely complain about the art. They complain about the plumbing: hooks that damage their `~/.claude/settings.json`, a pet stuck on "working" or showing ghost sessions, approval bubbles that linger or deny by accident, and overlays that swallow clicks, cover fullscreen apps or burn CPU. What users want is a trustworthy instrument first and a character second. The 2,118-reaction backlash over Anthropic removing `/buddy` shows the emotional pull is real, but Clippy's history shows what happens when a character interrupts. Nell's design already avoids the worst failure, because her hooks never touch global settings. Her open risks are in the less glamorous places: approval edge cases, stuck state after late hook events, and window and energy behaviour.

## Seven projects lead a field that is barely a year old

The category grew out of Claude Island (now Vibe Notch, created December 2025) ([vibe-notch](https://github.com/farouqaldori/vibe-notch)). Most of today's leaders were created between March and April 2026, and the field has since narrowed to a few healthy projects plus a long tail of single-author weekend repos. Star, contributor and release figures below were pulled from the GitHub API on 2026-11-14. Applying the inclusion rule strictly separates projects that are *established* from projects that are merely *starred*. Several high-star repos are dormant. **Vibe Notch** has 2.5k stars but no commits since 2026-04-20, and its forks (MioIsland, Buddi, VibeHub) now carry its ideas forward ([vibe-notch](https://github.com/farouqaldori/vibe-notch)). **agent-notch** has 313 stars but was created and last committed on the same day ([agent-notch](https://github.com/realfishsam/agent-notch)). **notchy** has 720 stars and was last pushed in March 2026 ([notchy](https://github.com/adamlyttleapps/notchy)); its feature set was not catalogued. Two separate codebases are both called "OpenPets". Neither is a GitHub fork of the other, both were created on 2026-05-04, and how they relate is unclear. **OpenPetsHQ/openpets** is the live one: an Electron pet platform with 1,399 stars, 29 contributors and v4.1.0 ([OpenPetsHQ](https://github.com/OpenPetsHQ/openpets)). **alterhq/openpets** is a Swift macOS pet driven over MCP, with 109 stars and no activity since May ([alterhq](https://github.com/alterhq/openpets)).

## The baseline is commoditized: hooks, a socket, Allow/Deny, fail-open

Across the leaders the architecture has converged. A hook script forwards each Claude Code event to the app over a **Unix socket or localhost HTTP** (Open Island, Notchi, Buddi, Hopet and MioIsland use sockets; clawd-on-desk uses ports 23333–23337). A state machine of roughly 7–12 states sits on top. The common states are idle, thinking, tool use, waiting for permission, done, error and sleep, and clawd-on-desk adds subagent and compaction states ([clawd state-mapping](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/state-mapping.md), [Hopet](https://github.com/BinaryFroggy/Hopet)). **Approval works only one way:** Claude Code's `PermissionRequest` hook blocks until the app answers. That is why agents whose hook runners cap handler time can't support approvals at all ([clawd known-limitations](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/known-limitations.md)).

The best practices are about failure, not features. Open Island's hooks **fail open**, so agents carry on unaffected if the app is not running ([Open Island](https://github.com/Octane0411/open-vibe-island)). When clawd-on-desk can't produce a decision (timeout, disconnect, do-not-disturb), its hook prints an empty decision so the agent's own prompt takes over. The bubble also dismisses itself if the user answers in the terminal first ([clawd state-mapping](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/state-mapping.md), [clawd features](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/features.md)). Hopet's design notes give two details worth copying. It ranks a pending question above a pending permission, because a permission can be cleared quickly from the terminal. And it dropped the `Notification` hook as a permission signal because it **double-fired alongside `PermissionRequest`** ([Hopet hooks doc](https://github.com/BinaryFroggy/Hopet/blob/HEAD/DevDocs/hooks-and-priority.md)). For customization, the **Codex Pets atlas** (`pet.json` plus an 8×9 or 8×11 grid of 192×208 frames) has become the interchange format. clawd-on-desk, Hopet, alterhq's OpenPets and Petdex all import it ([Petdex](https://github.com/crafter-station/petdex), [Hopet](https://github.com/BinaryFroggy/Hopet)).

Sending a free-typed prompt back into a session is still rare, and the reason matters for Nell. Hopet's maintainer **removed free-text input** after finding no reliable macOS way to inject text into an already-running session across terminals. They kept only answers that travel back through the hook protocol ([Hopet PR#2](https://github.com/BinaryFroggy/Hopet/pull/2)). claudlet can type into a session only on KDE through Konsole's DBus interface, and is "notes only" on macOS ([claudlet](https://github.com/YeeDochi/Claudlet)). clawd-on-desk's Telegram send falls back to the clipboard ([clawd known-limitations](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/known-limitations.md)). Every one of these apps attaches to terminals it doesn't own. A companion that owns its own terminal sidesteps the problem entirely.

## Users file bugs about config, wrong state and window layers, not art

clawd-on-desk's 443 issues are the richest record of user pain. The largest bug cluster, about 21–22 issues, is **hooks conflicting with the user's own config**. Examples: an invalid hook key made Claude Code throw a settings error ([clawd#19](https://github.com/rullerzhou-afk/clawd-on-desk/issues/19)), and on vibe-notch one bad key made Claude Code skip the whole settings file ([vibe-notch#85](https://github.com/farouqaldori/vibe-notch/issues/85)). An update deleted a user's `statusLine` ([clawd#848](https://github.com/rullerzhou-afk/clawd-on-desk/issues/848)). The app restored hooks a user had deliberately removed ([clawd#107](https://github.com/rullerzhou-afk/clawd-on-desk/issues/107)). Hooks were left behind after uninstall ([clawd#360](https://github.com/rullerzhou-afk/clawd-on-desk/issues/360)). Some hooks added up to 0.9 s per event ([clawd#1293](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1293)), and vibe-notch's hook crashed when `gettext` was missing ([vibe-notch#47](https://github.com/farouqaldori/vibe-notch/issues/47)). Users who run profile switchers or generate their settings dynamically treat silent edits as hostile, and one asked for hooks to ship as a plugin instead ([vibe-notch#7](https://github.com/farouqaldori/vibe-notch/issues/7)).

The second family is **state you can't trust**, and it is the longest-running problem on the largest repo. Reports include a pet that never reacts ([clawd#470](https://github.com/rullerzhou-afk/clawd-on-desk/issues/470), [vibe-notch#11](https://github.com/farouqaldori/vibe-notch/issues/11)), and a notch stuck on "Processing" because `PostToolUse` fired after `Stop` for a background Bash command ([vibe-notch#98](https://github.com/farouqaldori/vibe-notch/issues/98)). A subagent finishing was treated as the whole task finishing ([clawd#214](https://github.com/rullerzhou-afk/clawd-on-desk/issues/214), [vibe-notch#36](https://github.com/farouqaldori/vibe-notch/issues/36)). Ghost sessions filled the HUD across threads of 15 and 31 comments ([clawd#1073](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1073), [clawd#655](https://github.com/rullerzhou-afk/clawd-on-desk/issues/655)). Approval bubbles misbehave in about 13 issues. Approving one bubble auto-denied the others ([clawd#142](https://github.com/rullerzhou-afk/clawd-on-desk/issues/142)). Bubbles stayed up after the request was resolved elsewhere ([clawd#273](https://github.com/rullerzhou-afk/clawd-on-desk/issues/273), [clawd#988](https://github.com/rullerzhou-afk/clawd-on-desk/issues/988)). And a maintainer-filed bug found that closing the window sent Deny instead of falling back to the native prompt ([clawd#1100](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1100)). Users who chose auto or full-access modes resented a pet that forced approvals back on ([clawd#61](https://github.com/rullerzhou-afk/clawd-on-desk/issues/61), [clawd#322](https://github.com/rullerzhou-afk/clawd-on-desk/issues/322)).

The third family is the **window layer**, about 15–18 issues, and users want opposite things. Some want the pet shown over fullscreen Spaces ([clawd#27](https://github.com/rullerzhou-afk/clawd-on-desk/issues/27)). Others want it hidden for video ([clawd#1275](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1275)). Transparent areas eat clicks ([clawd#640](https://github.com/rullerzhou-afk/clawd-on-desk/issues/640), maintainer-filed; [openpets#41](https://github.com/OpenPetsHQ/openpets/issues/41)). Electron idle CPU reached about 45% on Apple Silicon ([clawd#244](https://github.com/rullerzhou-afk/clawd-on-desk/issues/244)), but native code is no guarantee of being light either: vibe-notch, which is native Swift, leaked to 64 GiB overnight ([vibe-notch#112](https://github.com/farouqaldori/vibe-notch/issues/112)). The few documented uninstalls are all trust failures, not taste: a window that moved the cursor ([vibe-notch#32](https://github.com/farouqaldori/vibe-notch/issues/32)), runaway memory, an app that would not quit ([vibe-notch#20](https://github.com/farouqaldori/vibe-notch/issues/20)), and one that relaunched after quitting ([clawd#911](https://github.com/rullerzhou-afk/clawd-on-desk/issues/911)). These counts are hand-tallied from titles, and issue trackers over-represent users who stayed. Reddit and X could not be read first-hand, and Show HN launches in this category drew six points or fewer ([HN](https://news.ycombinator.com/item?id=49819868)). The evidence is GitHub-heavy, and it says nothing about people who quietly left.

## Users want a trustworthy instrument first and a character second

The feature requests split into two camps. The instrument camp asks for more agents (the single largest request type, about 40 issues, e.g. [clawd#68](https://github.com/rullerzhou-afk/clawd-on-desk/issues/68)), remote or phone approval (about 15 filed by users, e.g. [clawd#493](https://github.com/rullerzhou-afk/clawd-on-desk/issues/493)), quota and context gauges ([clawd#112](https://github.com/rullerzhou-afk/clawd-on-desk/issues/112)), and plain text describing what the agent is doing right now ([clawd#1228](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1228)). They also want "generating" separated from "running a tool" ([clawd#1018](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1018), 13 comments), and end-of-task cards that persist because an animation is easy to miss ([clawd#1232](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1232)). One user explained that they work on another screen and miss that the agent has been waiting for ten minutes or more ([clawd#1368](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1368)). The same camp asks for ways to quieten the companion: still while working and playful when idle ([clawd#591](https://github.com/rullerzhou-afk/clawd-on-desk/issues/591)), no cursor eye-tracking ([clawd#1276](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1276)), and hideable pet stats ([openpets#82](https://github.com/OpenPetsHQ/openpets/issues/82)). Sounds cut both ways: one user credits a completion sound with stopping them drifting to social media ([clawd#64](https://github.com/rullerzhou-afk/clawd-on-desk/issues/64)), while false alerts annoy others ([vibe-notch#24](https://github.com/farouqaldori/vibe-notch/issues/24)).

The character camp is louder but narrower. The "Bring Back Buddy" issue drew **2,118 reactions and 287 comments** after Anthropic removed the in-terminal `/buddy` in v2.1.97. It is still active seven months later, although a "good riddance" comment drew 40 reactions ([claude-code#45596](https://github.com/anthropics/claude-code/issues/45596)). OpenPets users asked for voice ([openpets#10](https://github.com/OpenPetsHQ/openpets/issues/10)), and clawd-on-desk users asked for a pet with a built-in LLM ([clawd#1221](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1221)). That is a request for a companion you can *talk to*, which only a terminal-owning or LLM-backed design can deliver. Older desktop pets point the same way. Bongo Cat and RunCat last because they *react* to what the user is already doing, typing or CPU load, and never demand attention, while Clippy failed by interrupting with trivial help ([Insider Gaming](https://insider-gaming.com/what-is-bongo-cat-on-steam/), [RunCat](https://apps.apple.com/au/app/runcat/id1429033973?mt=12), [BGR](https://bgr.com/2155953/what-happened-to-clippy-why-microsoft-retired-office-assistant/)). The standard lesson is to design for the hundredth use, not the first ([TwentyBN](https://medium.com/twentybn/5-lessons-from-clippys-failure-efc69297eac1)).

Two platform sources settle the mechanics. Apple DTS's recipe for an overlay that survives full-screen Spaces has five parts: run as an accessory app, use a **non-activating `NSPanel`** (an `NSWindow` activates the app and can pull a full-screen app out of its Space), set level `.screenSaver` (`.floating` sits below full-screen content), add the `canJoinAllSpaces` + `fullScreenAuxiliary` + `stationary` collection behaviours, and set `hidesOnDeactivate = false`. DTS tested it on macOS 26 with a titled panel ([Apple Developer Forums 826308](https://developer.apple.com/forums/thread/826308)). Apple's energy guide notes that **a transparent window may count as visible**, so occlusion-based pausing will rarely fire for a pet, and the throttling has to be the app's own ([Apple: Work When Visible](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/WorkWhenVisible.html)). For fading chat, Raycast's Quick AI model avoids information loss with a light, floating surface that one keystroke promotes into a durable chat window ([Raycast manual](https://manual.raycast.com/v1/ai), [StarryHope](https://www.starryhope.com/mac/raycast-ai-mac/)).

## Conclusion

The landscape suggests Nell's most unusual decision, owning the terminal, matters more than her art. Every competitor attaches to terminals it doesn't control, and that is exactly why free-typed chat got removed (Hopet), confined to one Linux terminal (claudlet) or routed through the clipboard (clawd-on-desk). Nell's `kitten @ send-text` into a kitty instance she launched, together with `--settings`-only hooks, fills the niche the field left open: a floating macOS pet you can both talk to and approve from, which leaves no trace in global config. Both bets are still unproven, though, and the design doc rightly makes them the plan's first job.

The second lesson is that Nell's failure modes will be the field's failure modes in miniature. The bugs that dominate trackers are lingering bubbles, accidental denials, stuck "working" after late events, double-fired notifications and overlays covering or missing fullscreen. They don't disappear because Nell follows only one session. They are cheap to design out now and expensive to discover later, which is where most of the v1 additions below come from.

### Worth adding to v1

| Recommendation | Verdict | Reason |
|---|---|---|
| Use a **stable** hook endpoint: a fixed Unix socket path in App Support (`curl --unix-socket`), or a fixed port, never one chosen at launch | **(b)** | The design says kitty survives a Nell crash and Nell reconnects. But the running `claude` keeps the endpoint baked into its `--settings` file, so a new port would silently break hooks for that session. clawd-on-desk documents exactly this for dynamic ports ([clawd known-limitations](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/known-limitations.md)). | Settle an approval bubble the moment the request resolves in any way, including the user answering in kitty (signals to verify: the hook script's connection closing, or the next event for that session arriving) | **(b)** | The doc only handles timeout. The bubble that stays clickable after it stopped working is a top approval bug ([clawd#988](https://github.com/rullerzhou-afk/clawd-on-desk/issues/988), [clawd#913](https://github.com/rullerzhou-afk/clawd-on-desk/issues/913)). |
| Key each approval bubble to its own request; dismissing a bubble or quitting Nell means "no decision", never Deny | **(b)** | Subagents or parallel tool calls can produce more than one pending request. Answering one must not resolve the others ([clawd#142](https://github.com/rullerzhou-afk/clawd-on-desk/issues/142)), and close-means-deny was a real bug ([clawd#1100](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1100), maintainer-filed). |
| Ignore a `Notification` about a permission while a `PermissionRequest` is pending; show idle-waiting notifications at most once | **(b)** | Hopet dropped `Notification` as a permission signal because it double-fired ([Hopet hooks doc](https://github.com/BinaryFroggy/Hopet/blob/HEAD/DevDocs/hooks-and-priority.md)). Repeated alerts were a vibe-notch complaint ([vibe-notch#24](https://github.com/farouqaldori/vibe-notch/issues/24)). The doc maps both events independently. |
| Make `Stop` (and `StopFailure` / `SessionEnd`) final until the next `UserPromptSubmit`; ignore late `PostToolUse`; don't treat `SubagentStop` as done; add a watchdog that drops "typing" to idle after a few silent minutes | **(b)** | Stuck "Processing" after a background Bash ([vibe-notch#98](https://github.com/farouqaldori/vibe-notch/issues/98)) and subagent-finish-as-done ([clawd#214](https://github.com/rullerzhou-afk/clawd-on-desk/issues/214)) are classic. The state table has no rows for these events. |
| On `PostToolUse`, switch typing back to thinking until the next `PreToolUse` or `Stop` | **(b)** | This splits "generating" from "running a tool" ([clawd#1018](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1018), 13 comments) at the cost of one table row, using animations Nell already has. |
| Give AskUserQuestion its own bubble (question text plus "Answer in terminal"), not Allow/Deny, and rank it above permissions | **(b)** | Clicking Allow on a question picker is meaningless. Hopet ranks questions first because they can't be cleared quickly ([Hopet hooks doc](https://github.com/BinaryFroggy/Hopet/blob/HEAD/DevDocs/hooks-and-priority.md)). Clickable answer chips are (c). |
| Show a visible "hooks not connected" state if no `SessionStart` arrives within a few seconds of launching `claude` | **(b)** | "The pet doesn't react" is the commonest first-run failure ([clawd#470](https://github.com/rullerzhou-afk/clawd-on-desk/issues/470), [vibe-notch#11](https://github.com/farouqaldori/vibe-notch/issues/11)). This also makes the first-job checks visible in daily use. |
| Hook scripts: no dependencies beyond system tools, a sub-second connect timeout for non-blocking events, and the absolute path to `kitten` (kitty isn't on PATH) | **(b)** | Missing dependencies and slow hooks are recurring bugs ([vibe-notch#47](https://github.com/farouqaldori/vibe-notch/issues/47), [clawd#1293](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1293)). Notchi uses a 0.5 s timeout and exits silently ([Notchi hook](https://github.com/sk-ruban/notchi/blob/HEAD/notchi/notchi/Resources/notchi-hook.sh)). |
| Window recipe: non-activating `NSPanel` at `.screenSaver` level with `canJoinAllSpaces` + `fullScreenAuxiliary` + `stationary` and `hidesOnDeactivate = false`; verify it borderless on Darwin 27 | **(b)**: decide the level explicitly | The doc doesn't specify the window type. There is a real trade-off. At `.floating`, Nell vanishes behind full-screen apps; an approval isn't lost, because the deadline fallback raises kitty, but it waits up to the hook deadline. At `.screenSaver` (level 1000) she covers everything, which presses on the "gets in the way" anti-goal ([Apple DTS 826308](https://developer.apple.com/forums/thread/826308), [clawd#27](https://github.com/rullerzhou-afk/clawd-on-desk/issues/27) vs [clawd#1275](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1275)). Suggested: `.screenSaver` plus the Hide item below for video, since Nell is small and click-through. |
| Only the text field can take key focus, and only on an explicit user action (a click or the summon hotkey); bubbles never take focus | **(b)** | This is the Clippy interruption lesson, and it prevents fullscreen apps being knocked out of their Space ([Apple DTS 826308](https://developer.apple.com/forums/thread/826308), [clawd#538](https://github.com/rullerzhou-afk/clawd-on-desk/issues/538)). |
| Right-click menu gets **Hide Nell** (she returns automatically on the next needs-you) and **Quit** | **(b)** | Apps that wouldn't quit or hide drove uninstalls ([vibe-notch#20](https://github.com/farouqaldori/vibe-notch/issues/20), [clawd#1275](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1275)). Auto-return keeps hiding from losing an approval, which happened to clawd-on-desk's hotkeys while hidden ([clawd#601](https://github.com/rullerzhou-afk/clawd-on-desk/issues/601)). |
| Remember position per display, and pull Nell back on screen when a display disappears | **(b)** | Multi-monitor bugs recur in every repo ([vibe-notch#116](https://github.com/farouqaldori/vibe-notch/issues/116), [notchy#16](https://github.com/adamlyttleapps/notchy/issues/16), [openpets#56](https://github.com/OpenPetsHQ/openpets/issues/56)). |
| Energy: redraw only on frame change at pixel-art rates (about 6–12 fps), stop animating in sleepy, and pause on screen lock or display sleep | **(b)** | Apple says transparent windows may count as visible, so occlusion won't throttle Nell for her ([Apple: Work When Visible](https://developer.apple.com/library/archive/documentation/Performance/Conceptual/power_efficiency_guidelines_osx/WorkWhenVisible.html)). Idle CPU is a reported pain ([clawd#244](https://github.com/rullerzhou-afk/clawd-on-desk/issues/244)). |
| Start the fade timer on done and error bubbles only once the user is active again (system idle time, e.g. `CGEventSource.secondsSinceLastEventType`; check that it needs no permission prompt); pause fading on hover | **(b)** | Endings slip by when you're away ([clawd#1232](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1232), [clawd#1368](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1368)). This keeps the fade without losing the "done" you weren't there to see. |
| One soft sound for needs-you only, skipped when kitty is frontmost | **(b)** | This is the cheapest answer to missing a waiting approval on another screen ([clawd#1368](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1368)). Notchi's mute-when-focused rule avoids redundant alerts ([Notchi](https://github.com/sk-ruban/notchi)). Limiting it to one event respects the "not cluttered" anti-goal. |
| One global hotkey that shows Nell and focuses the bar | **(b)** | If Nell is to replace the Claude App, typing must not depend on aiming the mouse at her. Raycast's summon hotkey is the reference ([Raycast](https://raycast.com/core-features/ai)). Choose a chord that doesn't clash with shell bindings, the complaint against Vibe Island's shortcuts ([vibecoding.app](https://vibecoding.app/blog/vibe-island-review), unverified). |

### Later or not for Nell

| Recommendation | Verdict | Reason |
|---|---|---|
| Support for more agents (Codex, Gemini, opencode and others) | **(c)**, not for Nell | This is the field's top request, but it is the source of clawd-on-desk's ~52 KB caveat document ([clawd known-limitations](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/known-limitations.md)). Nell wraps Claude Code by design. |
| Several sessions at once, or one pet per session | **(c)**, later | This is a non-goal in the doc. It is also where ghost and undercount bugs live ([clawd#581](https://github.com/rullerzhou-afk/clawd-on-desk/issues/581)). Revisit only once single-session state is solid. |
| Remote or phone approval (Telegram, iPhone app) | **(c)**, not for v1 | These are loud asks ([clawd#493](https://github.com/rullerzhou-afk/clawd-on-desk/issues/493)), but Nell is scoped to one person at one Mac, and a network approval path widens the attack surface. While you're away, Claude simply waits and the approval falls back to kitty. |
| Quota and usage rings | **(c)**, later | clawd-on-desk reads the status-line `rate_limits` payload ([clawd features](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/features.md)). For Nell, adding a `statusLine` to her `--settings` would likely replace the user's own status line in her sessions (unverified), and it adds clutter. |
| Global Allow/Deny hotkeys | **(c)**, later | Requested ([clawd#64](https://github.com/rullerzhou-afk/clawd-on-desk/issues/64), [clawd#70](https://github.com/rullerzhou-afk/clawd-on-desk/issues/70)), but an accidental global Allow is worse than a click. Revisit once usage shows it's wanted. |
| Answer chips for AskUserQuestion and diff previews in approvals | **(c)**, later | Proven by Hopet and MioIsland ([MioIsland zh](https://github.com/MioMioOS/MioIsland/blob/HEAD/README.zh-CN.md)), but the exact `updatedInput` schema is unverified here, and "Answer in terminal" covers v1. |
| Codex Pets atlas import, a skin or theme format, a weighted-random idle table | **(c)**, not for Nell | These drive retention for multi-user pets ([Petdex](https://github.com/crafter-station/petdex)), but Nell is one specific character. Idle variety belongs to the art track. Confirm with a sample export that Aseprite's JSON carries per-frame durations, since the CLI docs don't say ([Aseprite CLI](https://www.aseprite.org/docs/cli/)). |
| Gamification (XP, feeding, stats) or sentiment-driven moods | **(c)**, not for Nell | Some users find stats annoying ([openpets#82](https://github.com/OpenPetsHQ/openpets/issues/82)). Notchi's sentiment feature sends prompts to an external API ([Notchi](https://github.com/sk-ruban/notchi)), which conflicts with the doc's "no separate model call" non-goal. |
| Subagent visualisation (juggling, followers) | **(c)**, later | It is a second-wave feature in the field ([clawd features](https://github.com/rullerzhou-afk/clawd-on-desk/blob/HEAD/docs/guides/features.md)). Getting `SubagentStop` handling correct (see (b)) comes first. |
| Following Claude Desktop or sessions Nell didn't start | **(c)**, not for Nell | Users repeatedly ask for this ([clawd#1252](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1252)), but it would bring back global hooks or transcript scraping, the exact sources of the bugs Nell avoids. |
