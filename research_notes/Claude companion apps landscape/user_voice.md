Duplicate filings count once (#591/#592, #552/#553, #515/#516, #1119/#1120). On clawd-on-desk, reactions are close to zero on nearly every issue (the maximum outside the license issue is 2), so comment count is the only usable signal of intensity there.

- **Survivorship bias:** issue trackers over-represent engaged users who stayed. People who uninstalled mostly leave no trace.
- **Secondhand sources** (web search and fetch summaries, vendor and review blogs) are paraphrased and marked "unverified" where the underlying user comment could not be seen.

## Q1. What do GitHub issues on the popular companion repos ask for and complain about most?

### Takeaway
The dominant theme is not the pet. It is plumbing: hooks breaking or overwriting users' own settings, the pet showing the wrong state (ghost or stuck sessions), approval bubbles misbehaving, and a long tail of "support my agent" requests. Next come window-layer problems (fullscreen, multiple monitors, swallowed clicks, ghost taskbar icons) and idle CPU use. Requests cluster around remote and mobile approval, usage and quota display, richer "what is it doing" text, and options to make the companion quieter or less intrusive.

The maintainer confirmed that older versions left Clawd hooks in agent config files after the app was removed, and shared a cleanup script. The current answer is to uninstall each integration in Settings first; just disabling it does not remove the hooks.
- **Would not stay quit:** after the user quit and disabled autostart, Keychain prompts kept appearing, and denying them relaunched the app ([clawd#911, 2026-08](https://github.com/rullerzhou-afk/clawd-on-desk/issues/911)). This was fixed in v0.16.0. A process also kept scanning processes after quit ([clawd#681, 2026-07](https://github.com/rullerzhou-afk/clawd-on-desk/issues/681)).
- **Breaks other fullscreen use:** fullscreen games minimizing about every 5 s ([clawd#538, 2026-06](https://github.com/rullerzhou-afk/clawd-on-desk/issues/538), [clawd#688, 2026-07](https://github.com/rullerzhou-afk/clawd-on-desk/issues/688)). Videos covered by the always-on-top pet ([clawd#1275, 2026-10](https://github.com/rullerzhou-afk/clawd-on-desk/issues/1275)).
- **Violates the agent's design:** forced approvals on Pi that cannot be turned off ([clawd#322, 2026-05](https://github.com/rullerzhou-afk/clawd-on-desk/issues/322)).
- **Unverified (vibecoding.app review of the paid Vibe Island, 2026-08-29):** the review reports two unnamed buyers. One stopped using it as the interface wore thin. The other complained that an update turned on global shortcuts by default that overrode shell bindings such as clearing a line ([vibecoding.app](https://vibecoding.app/blog/vibe-island-review)).

### Inferences
- **The integration layer is the product.** Most user pain is about hook reliability, config ownership and correct state, not art. A companion that edits `~/.claude/settings.json` is entering users' carefully managed config. Several users already run profile switchers, dynamically generated settings or synced settings, and treat silent edits or re-adding of hooks as hostile ([clawd#107, 2026-04](https://github.com/rullerzhou-afk/clawd-on-desk/issues/107), [clawd#395, 2026-06](https://github.com/rullerzhou-afk/clawd-on-desk/issues/395), [vibe-notch#7, 2025-12](https://github.com/farouqaldori/vibe-notch/issues/7)).
- **The trust bar on state is high.** A pet that says "working" when nothing is running, or misses a pending approval, is worse than no pet. Ghost and stale sessions are the most persistent multi-month bug family on the largest repo.
- **Intrusiveness wants opposite things from different users.**
  - **Fullscreen:** some want the pet over fullscreen, others want it hidden.
  - **Approvals:** some miss approvals, others say the pet adds prompts to auto or YOLO flows.
  - **Sound:** some want it, others hit false triggers.
  - **Liveliness:** some want more animation, others call it a distraction.

  That points to per-behaviour toggles with conservative defaults, not one "right" setting.
- **"Claude Desktop is not covered" is a real gap.** Nearly every tool keys off CLI hooks. Users on Claude Desktop, Cowork or the VS Code extension repeatedly find nothing happens.

### Gaps
- **Reactions:** reaction counts are near zero on clawd-on-desk, so intensity is inferred from comments, which mixes in maintainer back-and-forth.
- **Origin of issues:** I did not quantify the share of issues opened by maintainers versus outside users.
- **ClaudePet:** `qaz61328/claudepet` returned 404. There may be a renamed repo I did not find.
- **Discussions tabs:** GitHub Discussions were not read. Only issues were.
- **Buddi and Hopet:** both have too few user issues to rank anything. Their trackers are mostly maintainer PRs.

## Q4. What do people want from "a companion" beyond status?

### Takeaway
Two camps. One wants a quiet, trustworthy instrument: status, approvals, quota, and an off switch. The other wants a character with personality, voice or chat, growth, and wellbeing nudges. The character camp is loud: 2,118 reactions on /buddy, and pet-submission traffic on OpenPets. But some in it find stats and motion distracting. Chat-from-the-pet is wanted, but one maintainer found it technically hard to inject typed input back into an already-running terminal session.

### Cited Findings
- **Personality and talking:**
  - **Buddi:** a user asked to use the user's actual hatched /buddy and give it a personality and comments ([Buddi#2, 2026-04](https://github.com/talkvalue/Buddi/issues/2), 2026-04-15). ### Inferences
- **Personality and attachment are real, persistent drivers.** The /buddy thread is still active 7 months later, and forks add emotions and treats ([vibe-notch#89, 2026-04](https://github.com/farouqaldori/vibe-notch/issues/89)). But they must be layered optionally over a reliable status and approval core, with toggles for stats, motion and sound.
- **Chat that can only answer the agent's own prompts** (approvals, AskUserQuestion) is feasible through hooks. Free-form "talk to my running Claude session from the pet" needs a different architecture, such as launching or owning the session, or a separate LLM.
- **Wellbeing features are mostly single-author proposals.** They are unproven demand, but they fit the existing signal data.

### Gaps
- **Retention:** no data on whether gamified or chat companions keep users longer than status-only ones. The /buddy thread includes one anecdotal claim that sessions got shorter after removal.
- **Pomodoro:** no first-hand data on pomodoro or reminder usage, beyond OpenPets having a plugin and a bug report.
